# Partner Security Portal

Use this reference for Source Code Scanner access or office-hours routing. The
portal is an authenticated external system: explain the current documented
path in Ask, inspect only partner-supplied evidence in Assess, and require a
bounded plan and explicit approval before any Act operation.

## Access and scanner preparation

- The user must be an ISV partner with a Partner Community account.
- Connect the Developer Edition Dev Hub or packaging org that hosts the work to
  the AgentExchange Partner Console, then use that org's credentials to log in.
- Current official guidance identifies `Manage Listings` for Partner Console
  and Security Review access and `Author Apex` for the Source Code Scanner.
  Verify permissions from current sources before prescribing access.
- Link the package version to an AgentExchange listing before a Partner Security
  Portal Checkmarx scan.
- Current guidance includes three Source Code Scanner runs per package version
  with the review fee. Preserve those runs for finalization and refresh the
  limit before relying on it.

Do not collect, display, or persist portal, org, external-service, or test-user
credentials in the readiness dossier. Record only the owner, secure delivery
location, validity, and whether Product Security can exercise the test path.

## Office-hours routing

- **Operations office hours:** review scope, required reports and materials,
  submission logistics, related cases, and what happens after a result.
- **Technical office hours:** secure design, scanner findings, remediation,
  false-positive interpretation, review-report findings, and validation of a
  proposed fix.

Scheduling is an external mutation. Show the intended appointment type,
question, disclosed context, portal destination, and owner, then obtain explicit
approval. The partner signs in and supplies credentials through the portal;
never request that they paste credentials into the advisor conversation.
